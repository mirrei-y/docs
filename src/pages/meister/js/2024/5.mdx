## URL

まず、HTTP に重要である URL (Uniform Resource Locator) について軽く説明します。
URL は、通信方式と、通信先のサーバー、取得したいページのファイル名が記載されています。

URL は以下のような書式で成り立っています。
```
プロトコル://ホスト名/ファイル名
```

例えば、今見ているこのページの URL は
```
https://docs.mirrei.dev/meister/js/2024/5
```
であるので、プロトコルは `https`、 ホスト名は `docs.mirrei.dev`、 ファイル名は `/meister/js/2024/5` です。

<Tips>
プロトコルは `http` ではなく、 s がついた `https` となっています。
このサイトは HTTP で通信しデータを取得していますが、 `https` は暗号化された HTTP を使用するという意味になります。

本記事では解説しませんが、暗号化についてもプロトコルが存在します。
現在主流のものは TLS というプロトコルですので、気になる方は各自調べてみてください。
そういえば、この手の暗号化通信については、1年生の「情報基礎」で任意課題としてレポートに出ていた記憶があります。
</Tips>

<Tips>
URL に使用できるプロトコルは `http` のみではありません。
例えば、ファイル転送プロトコルである `ftp` や、サーバー制御のプロトコルである `ssh` などがあります。

また、ほかの人と被らなければ（最悪かぶっても問題はないのですが）、自分で名乗って使用することもできます。
星の数ほどあるので、本記事では解説しません。
</Tips>

## HTTP/1.1

### 概要

HTTP とは、Hypertext Transfer Protocol の略で、主に Web ページのデータを転送するための通信プロトコルです。

私たちが Web ページを見るとき、Web ページのデータはインターネットを通じてどこかにあるサーバーと通信し、必要なデータをダウンロードしています。
その際の通信の約束事（プロトコル）が HTTP です。

### 利点

これを覚えておくと、例えばいわゆるサーバーを作成したり、JavaScript を使って、Web ページを取得した後も追加のデータを取得するプログラムを書くことができるようになります。
サーバーは Web ページのデータを送信する役割を果たすため Web ページを見るのに必須と考えられますが、「追加のデータを取得する」というのは必要なのでしょうか。

### リクエスト

今回は、テキストベースかつシンプルな HTTP/1.1 と呼ばれるバージョンの HTTP を学習していきます。

クライアントが Web ページをダウンロードする際、まずクライアントはサーバーに対して以下のようなリクエストを送信します。

```
GET /meister/js/2024/5 HTTP/1.1
Host: docs.mirrei.dev
Accept: */*

```

`GET` は、そのファイル（リソースといいます）に対してどのような操作を行うかを指定します。
これを、「リクエストメソッド」と呼びます。
リクエストメソッドには、`GET`, `POST`, `DELETE` などが指定できます。
その後、スペース区切りでパス名とHTTPのバージョンを送信します。

<CaptionImage src="/attachments/meister/js/2024/5/http-request.webp" caption="HTTP リクエスト。@IT による、『「HTTP」の仕組みをおさらいしよう』の 図 7 を引用。" />

### リクエストヘッダー

この時点で1行目が終了し、その後は「リクエストヘッダー」という情報群になります。

ヘッダーは、リクエストに追加データを付与するもので、`(キー): (値)` という書式で書きます。

代表的に、以下のようなヘッダーがあります。

| ヘッダー | 用途 |
| - | - |
| Host | 宛先ホスト名をサーバーに知らせる |
| Accept | ブラウザが表示できるファイルの種類を、ブラウザが自己申告する |
| User-Agent | ブラウザ名やバージョンを知らせる |
| Cookie | 「Cookie を許可しますか？」のアレ。サーバー側が、クライアントに一定量のデータを保存できるCookie機能で使用される |
| Connection | リクエスト・レスポンスが終了した後、接続を切断するかどうか設定する |

<Tips>
[MDN Web Docs: リクエストヘッダー](https://developer.mozilla.org/ja/docs/Glossary/Request_header) では、より詳しいリクエストヘッダー一覧を見ることができます。

また、ヘッダー一覧は [MDN Web Docs: HTTP ヘッダー](https://developer.mozilla.org/ja/docs/Web/HTTP/Headers) で見ることができます。
</Tips>

### レスポンス

サーバーは、このリクエストに対し以下のようなレスポンスを送信します。

```
HTTP/1.1 200 OK
Date: Sun, 23 Jun 2024 22:49:18 GMT
Content-Type: text/html
Content-Length: 8888

... HTMLデータ ...
```

### レスポンスヘッダー

リクエストヘッダーと同様に、レスポンスにもヘッダーを含めることができます。

代表的に、以下のようなヘッダーがあります。

| ヘッダー | 用途 |
| - | - |
| Content-Type | ファイルの内容の種類（text/html, application/javascript など。詳しくは [MIME タイプ](https://developer.mozilla.org/ja/docs/Web/HTTP/Basics_of_HTTP/MIME_types) を参照） |
| Content-Length | ファイルサイズ |
| Date | レスポンスが生成された時刻 |
| Server | サーバー名 |
| Set-Cookie | サーバーが指定する、Cookie に保存するデータ |

<Tips>
[MDN Web Docs: レスポンスヘッダー](https://developer.mozilla.org/ja/docs/Glossary/Response_header) では、より詳しいレスポンスヘッダー一覧を見ることができます。

また、ヘッダー一覧は [MDN Web Docs: HTTP ヘッダー](https://developer.mozilla.org/ja/docs/Web/HTTP/Headers) で見ることができます。
</Tips>

### curl コマンドで実際の通信を行う

ではここで Windows を例に実演してみましょう。

`Windows` + `R` を押して、出てきた「ファイル名を指定して実行」ウィンドウに `cmd` と入力し、Enter を押してください。

<CaptionImage src="/attachments/meister/js/2024/5/command-prompt.webp" caption="Windows のコマンドプロンプト。" />

この画面で、`curl`（「カール」と読みます）という HTTP 通信を行えるソフトウェアを呼び出します。

URL は引数として指定します。
コマンドはスペース区切りで引数を指定できます。

```bash
curl https://mirrei.dev
```

このコマンドを入力し、Enter キーで実行してみましょう。

<CaptionImage src="/attachments/meister/js/2024/5/command-prompt-curl.webp" caption="curl の実行結果。" />

実際に HTML で記述された Web ページを呼び出すことができました。

#### ヘッダーも見る

`curl` の機能として、リクエストヘッダー・レスポンスヘッダーも見ることができます。

URL の前に `-v` をつけることで、その機能が有効になります。

```bash
curl -v https://mirrei.dev
```

## HTTP/2, HTTP/3

先ほどまでに説明した内容は、HTTP の別のバージョンである HTTP/2 と HTTP/3 でも重要な知識です。

今回は説明しませんが、HTTP/2 は HTTP/1.1 の欠点であった通信量が大きいこと、HTTP/3 は HTTP/2 の欠点であった通信のタイムラグを削減することができるプロトコルです。
どちらも、HTTP/1.1 で採用されていたテキストベースではなく、バイナリベースでの通信です。

この Web ページでは主に HTTP/2, HTTP/3 が使用されています。
